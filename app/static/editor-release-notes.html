v1.1.0 current

2026-10-24

Added

  • Next and Prev cross surah boundaries. Next on the last ayah opens the next surah's first ayah, and Prev on the first opens the previous surah's last — segmenting a surah does not end at its last verse. The ends of the Qur'an still say so and stay put. Ctrl+Enter crosses too, since it reuses the same navigation.
  • The editor opens where you left off. Your last ayah is remembered per translation, and a bare /editor returns to it; a link that carries surah/ayah always opens exactly where the link says. The same applies to each reader, independently.
  • Your edits are your own. A save from this account writes a private copy of that ayah, so two people can segment the same verse without overwriting each other. Readers fall back to the shared text ayah by ayah, so an ayah you have not touched still shows the shared segmentation. An administrator can approve one of your ayahs into the shared text.

Fixed

  • The page could be served from cache. The editor, its release notes and the mushaf reader were the only pages sent without Cache-Control, so a browser was free to keep an old copy and make a fix look like it had not been applied. All three are now served no-cache.
  • Crossing a surah could leave the page lying about where it was. The surah selector was changed before the new surah had loaded, so a failed request left it pointing at surah 2 while the ayahs, heading and segments still belonged to surah 1. The previous position is now restored, with a message saying nothing changed.

v1.0.0

2026-10-18 · first versioned release

Editor features

  • Split an ayah into segments, each a range of whole Arabic words plus its own translation text. Boundaries always fall between words, anchored to ayah_words indices, so a segment is stable across normalisation or re-import.
  • Segments must cover every word exactly once, in order, with no gaps or overlaps; the editor refuses a save that would leave a hole.
  • Merge next, Split, Delete and per-row ✎ Edit to shape the table without starting over.
  • Save overwrites all segments for that (translation, surah, ayah) in one request; AutoSave saves before Prev/Next so nothing is lost while working through a surah.
  • 👁 Show original translation shows the pristine whole-ayah text from translation_originals as a read-only reference.
  • Surah, ayah and translation selectors are all populated from the database. The URL always carries translation_id, surah and ayah, so a link returns to the same verse.
  • Keyboard: P / N previous / next ayah, Alt+A add segment, Alt+S save, Ctrl+Enter save and go next, Enter in the translation box adds a segment.

Added in this version

  • Version badge. The toolbar shows the editor version (currently v1.0.0) and links to these notes. The version lives in one place — EDITOR_VERSION in editor.html.
  • + Add segment with nothing selected now assigns the whole remainder — every un-assigned word plus the remaining translation — as the final segment. If no segment exists yet, it becomes the first. An empty segment is never added: if nothing is left, it says so. Nothing is saved until Save.
  • Clearing a selection. Esc — or clicking the already-selected word again — clears a stray word (and translation) selection, so + Add segment goes back to taking the whole remainder instead of insisting on a matching translation.
  • Warning before leaving unsaved work. With AutoSave off, navigating away from an ayah that has unsaved changes now asks Save and continue / Discard and continue / Cancel instead of silently discarding. The same question guards the surah, ayah and translation selectors, and closing or reloading the tab triggers the browser's own prompt.

Changed

  • Translations come from the database (GET /translations) instead of two entries hardcoded into the page, so a translation added to the table is selectable immediately. When the URL names no translation, the first in the table is used.
  • Navigation arrows follow the reading direction — Prev ▶ and ◀ Next — and ◀ Next now sits before Prev ▶, so each button is on the side its arrow points to. The keyboard mapping is unchanged (P = previous, N = next).
  • Arrow keys in the script follow its direction: ← selects the next word and → the previous one, since the script reads right-to-left. The first press selects the first word rather than skipping past it.
  • Translation selection is word-based. The remaining translation is shown as one chip per space-separated word, so a partial word can no longer be selected. Click, shift+click, the arrow keys and Esc behave exactly as they do for the script, and punctuation that follows a word — a full stop, comma or exclamation, including a bare punctuation token — is absorbed into the segment even if it was not clicked. The raw text is still editable through ✎ Edit translation.
  • Whole words or free characters. A Select whole words checkbox (on by default, next to Edit translation) switches the translation back to free character selection in the read-only text — the only way to place a boundary where two words have no space between them. In that mode the counter shows characters instead of words.

Fixed

  • Start over scrambled the translation. It merged the segment texts back into the work area in segment order, which only reproduced the original sentence when the segments happened to be in text order — assigning a word from the middle of the translation to the first words of the ayah moved that word to the front and the order could not be recovered. Start over now reloads the ayah from the database, matching what a page refresh gives you.
Cutting a version. Bump EDITOR_VERSION in editor.html once the batch of changes is final — not on every intermediate edit — then add a section to this page with the matching anchor (id="v1.0.1" etc.) describing what changed. The badge links to /editor/release-notes#v<version>, so the section anchor is what makes the link land on the right release.
