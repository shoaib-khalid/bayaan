Checking API…

Pages

  • home/ This page — every link in one place.
  • /reader?translation_id=2&surah=1 Reader — Phrase layout (default): each segment's Arabic line with its Urdu tucked underneath.
  • /reader?layout=inter&translation_id=2&surah=1 Reader — Lines layout: one Arabic line + one Urdu line per segment, as a block.
  • /reader?layout=flow&translation_id=2&surah=1 Reader — Flowing layout: full ayah justified, translation below it.
  • /reader-mushaf?translation_id=2&surah=1 Mushaf reader (Layout B): each word tinted by its segment, laid out on a fixed portrait page with page-turn navigation, A−/A+ text size, and swipe/keyboard paging across surahs.
  • /editor?translation_id=2&surah=1&ayah=1 Segment editor: split an ayah into word-anchored segments. Press ? in the page for the usage guide.

API — JSON endpoints

  • /surahs All 114 surahs with name_arabic, name_english, ayah_count.
  • /surah/{surah_id}?translation_id= Everything a renderer needs — per ayah: words[] with is_word, and segments[] with word-index bounds + translation_text.
  • /original/{translation_id}/{surah}/{ayah} Pristine whole-ayah translation from translation_originals (the editor's "Show original").
  • /ayah/{surah}/{ayah} Legacy — Arabic words of one ayah.
  • /segments/{translation_id}/{surah}/{ayah} Legacy — segments of one ayah.
  • POST/segments Overwrite all segments of an ayah. Not clickable — needs a JSON body, and its start/end semantics contradict the FK (see open task).

Documentation

  • /docs Swagger UI — try every endpoint interactively.
  • /redoc ReDoc — the same API as reference documentation.

Note on pagination: /reader-mushaf draws a fixed portrait page and divides it by measured line boundaries, so a page may break mid-ayah or mid-segment but never slices a line in half. Page contents depend only on the text size, not the window: resizing scales the page like an image. /reader still renders a whole surah as one continuous scroll.
